# Build Glossary

## Vertical slice
One small product capability built through every required layer: user interface, business rules, API, database, security, accessibility, and tests. For this package, the slice runs from evidence capture through resume-component certification.

## TypeScript domain model
A typed definition of the product's core business objects and permitted values. It helps prevent inconsistent or unsupported data from entering the system.

## Runtime schema
A validation rule that checks real data while the application is running. TypeScript checks developer code; runtime schemas check user and API data.

## Service guard
A business-rule check that blocks an action when required evidence, status, permission, or approval is missing.

## Database migration
A versioned file that creates or changes database structures in a repeatable, auditable way.

## API contract
The agreed request, response, error, and authorization shapes used by the frontend and backend to communicate.

## Frontend state
A named condition the interface can be in, such as loading, saved, blocked, verified, or certified.

## Automated test scaffold
A prepared test structure containing test cases or placeholders. A scaffold is not the same as a completed test suite.

## Source control
A system that records code history, versions, branches, and changes. Git is the source-control system; GitHub is one hosting and collaboration platform for Git repositories.

## Continuous integration (CI)
An automated process that installs dependencies, compiles code, and runs checks whenever changes are submitted.
